# Rift Wizard 3 — 网页复刻版（简体中文）

《**Rift Wizard 3**》（Dylan White / Khoops / Jacob Martinez）的浏览器复刻版：
硬核回合制网格 Roguelike，巫师穿越二十个领域，法术池完全开放、每个法术四选二升级、
神器由裂隙中拾取的材料熔铸而成。

全部代码与美术均为原创，**未使用原作任何素材**。这是对其**系统**的复刻，不是移植。
游戏界面、法术、怪物、神器、日志全部为简体中文。

## 在线试玩

**<https://liutower.github.io/rift-wizard-3-web/>** —— 无需安装，浏览器打开即玩。

每次推送到 `main` 由 GitHub Actions 自动构建部署；类型检查或测试不通过则不会上线。
Actions 约半分钟跑完并把产物推到 `gh-pages` 分支，之后 Pages 后台还要约十分钟
才会真正生效——改动没立刻出现是正常的，等等再刷新。

## 运行

```bash
npm install
npm run dev      # http://localhost:5273
npm run build    # 产物在 dist/（约 331 kB，gzip 后 90 kB）
npm run preview  # 预览生产构建
npm test         # 内容契约 + 自动对局测试
npm run typecheck
```

零运行时依赖：Vite + TypeScript，棋盘用 canvas，面板用 DOM，音效用 WebAudio 合成。
**不含任何图片与音频文件**——精灵图是矢量形状 DSL 在运行时栅格化的。

## 新手教学

标题界面按 `T`。两层手工关卡、27 步脚本流程，覆盖全部核心机制：

| 层 | 教什么 |
| --- | --- |
| 第一层 · 残垣厅堂（19 步） | 八方向移动 · 检视面板 · 视线阻断 · 巫师不能近战 · 施法与瞄准 · 范围落点 · 回合交替与等待 · 硬抗性（火抗 50% / 冰抗 −50% 的赤色软泥）· 死亡分裂 · 技能点与法术商店 · 升级四选二 · 持续伤害 · 召唤物 · 充能与法力药剂 · 拾取材料 · 飞行与深渊 · 裂隙预览 · 传送门 |
| 第二层 · 白骨陵墓（8 步） | 刷怪门与目标优先级 · 增益单位 · 锻造神器 · 装备加成生效 · 治疗药剂 · 清空领域 |

流程是**确定**的：每一步只放行它要求的那一个操作，其余会被拒绝并在日志里给出提示
（"这一步请施放指定的法术"）。三个例外永远放行，否则玩家会被卡死：**移动**（重新
取位的唯一手段，且有几步的目标故意放在射程外）、**检视**（只读状态），以及关闭面板 /
`ESC` 暂停菜单 / `H` 玩法说明这几个逃生口。教学中巫师不会死亡——归零时回满并提示。

门控收口在 `Game`（`tutorialAllows` / `canOpenPanel`）而不是 UI 层：操作来自键盘、
棋盘点击、覆盖界面点击三处入口，任何一处漏检都会让"确定流程"失效。

## 复刻了哪些机制

- **回合制网格战斗。** 你行动一次，然后所有其他单位行动。没有命中判定：伤害是确定的，
  抗性是百分比（100 为免疫，负值则额外受伤），护盾可完整抵挡一次伤害。
- **巫师不能近战。** 一切都靠施法。站位、视线与位移法术是你全部的防御手段。
- **完全开放的构筑。** 法术池中任何法术都可随时在角色面板用技能点购买。每个法术提供
  四项升级，你可以选两项——本局永久生效。
- **充能制，不是法力值。** 法术有充能，进入新领域时回满。法力药剂**一次补满所有法术**，
  所以法术书越宽，每瓶药剂的收益越高。
- **锻造取代被动技能**（这是 RW3 的改动）。领域中会掉落材料（`U T C H B I S O` 八种），
  配方将其熔铸成神器，占据九个装备槽位，提供按标签作用域生效的加成，例如
  「火焰法术 +2 伤害」或「所有法术 +1 充能」。其中十件神器带有真实触发效果
  （击杀时、施法时、受伤时、移动时、每五回合）。
- **传送门带诚实预览。** 每次清空领域后提供三个裂隙；预览会列出生态、标签、奖励
  以及你将要面对的精确怪物名单。每领域可免费重掷一次。
- **领域推进。** 共二十个领域；首领分别位于第 8、13、17 领域，莫德雷德在第 20 领域。
  清空一个领域可获得 3-5 技能点。
- **云雾、深渊、可破坏地形。** 危险云雾每回合造成伤害，非飞行单位被推入深渊即死，
  多个法术可以创造或摧毁地形。
- **刷怪门与增益单位。** 门会持续产出怪物，祭司会强化同伴，所以目标优先级比纯输出更重要。
- **永久死亡 + 自动存档**（进入新领域时存档；死亡后存档删除）。

## 与原作的有意差异

- 内容是精选子集，而非原作完整的 500+ 法术池。
- 巫师每清空一个领域获得 **+9 生命上限并恢复 20% 生命**。原作依靠远大得多的神器池
  提供这条成长曲线；在物品数量较少的情况下这样才能保证一局可通。
- 首领固定出现在特定深度，而非作为游荡的传奇生物随机出现。
- 每个召唤者同时最多维持四个存活召唤物，因此刷怪门是持续压力，而不是超过任何清理
  速度的无限雪球。
- 存档恢复你的构筑，并用种子重新生成当前领域，而不是保存关卡中途状态。
- 美术是运行时生成的程序化矢量线稿，音效是合成的，不含任何素材文件。

## 架构

```
src/
  core/          引擎，不接触 DOM（约 3.4k 行）
    types.ts     伤害类型、标签、材料、槽位、加成表、中文显示名映射
    rng.ts       带种子的 xoshiro128**（同一种子可复现）
    geom.ts      网格数学：球形、环形、锥形、直线
    level.ts     地块、单位、云雾、物品、传送门、视线、流场
    unit.ts      Unit + Buff + 声明式怪物 Attack
    combat.ts    唯一的伤害管线、buff、召唤、位移效果
    spell.ts     SpellDef/SpellInst、属性解析、瞄准规则
    buffs.ts     以 id 索引的状态效果库
    clouds.ts    云雾库
    fx.ts        视觉特效队列，按“节拍”回放
    ai.ts        怪物回合：技能选择 + 流场移动
    levelgen.ts  洞穴挖掘、怪物预算、战利品、传送门放置
    realm.ts     生态、领域/传送门生成、难度曲线
    game.ts      局内状态、回合循环、商店/锻造入口、存档
    registry.ts  通过 import.meta.glob 自动注册内容
    crafting.ts  配方、装备、加成重算
    tutorial.ts  两层手工教学关卡、27 步脚本与操作门控
  render/        精灵图 DSL、程序化地块纹理、canvas 棋盘（约 0.9k 行）
  ui/            状态栏/战报栏、覆盖界面、输入（约 1.0k 行）
  content/       纯数据包：法术、怪物、神器、物品（约 7.5k 行）
  audio.ts       程序化 WebAudio 音效
```

游戏逻辑是同步的；视觉通过特效队列（`core/fx.ts`）解耦，渲染器按“节拍”回放——
所以一个回合瞬间结算，但看起来是有动画的。

新增内容只需在 `src/content/` 放一个文件，导出 `spells`、`units`、`artifacts`、
`consumables`、`sprites` 中的任意项。完整契约见
[`docs/content-guide.md`](docs/content-guide.md)（类型与 API，英文），
中文文案规范见 [`docs/i18n-glossary.md`](docs/i18n-glossary.md)（术语表）。

开发模式下 `window.__rw3` 暴露 `{ game, board, refresh }` 供控制台调试，生产构建会剥离。

## 测试

`npm test` 运行四个文件共 24 项检查。

`test/content.test.ts` —— 内容契约：

- 每个法术都有四项唯一升级和一个施法风格标签
- 内容引用的每个精灵图 key 都存在
- 怪物生命值落在其等级区间内、召唤 id 可解析、非首领最多一个远程技能
- 怪物数据引用的每个 buff 与云雾 id 都能解析（缺失的 id 会静默失效，必须拦住），
  并锁定文档中公开的 buff 集合
- 四个首领都存在；两种必备消耗品都存在
- 法术池中每个法术都能生成描述并成功施放（含带升级与不带升级两种情况）

`test/playthrough.test.ts` —— 由脚本巫师驱动的真实对局：

- 五局“笨”对局不得卡死，且至少要打到第 4 领域（通常死在第 8-13 领域）
- 六局使用预设法术清单与充裕技能点收入的对局不得卡死，且至少一局要清空全部二十个
  领域并击杀莫德雷德（当前六局中四局通关，约 500 回合、30 个法术、3-7 件神器）
- 进入新领域时充能回满并获得技能点

卡死检测器会在领域无法完成时打印完整棋盘状态（敌人可达性、视线、剩余充能）。
开发期靠它定位了三个真实的死锁缺陷：流场给“单位自身所在格”加成本（导致任何移动者
在两格间无限摆动）、召唤者没有存活上限、以及召唤物会把巫师推回原地。

`test/mapgen.test.ts` —— 关卡生成可达性审计（120 个种子 × 20 领域 = 2400 张地图）：

- 战利品、传送门、地面敌人都不得被隔在巫师走不到的地方
- 不得留下巫师无法抵达却可站立的地板
- 巫师可走面积必须占关卡内部面积的 55% 以上

最后一项是为一个真实缺陷立的门槛：`carve` 原本用「保留最大连通块、其余填成墙」来
保证连通性，随机游走墙叠加深渊把洞穴切碎时，可走面积最低只剩 **34%** —— 玩家会被
封在角落，看到的「地图另一边」全是实心墙。现在改为给每个孤立区域挖一条通往主洞穴的
对角通道（碎屑填平），最差情况回到 63%，而中位数 73% 保持不变 —— 只修病态尾部，
不改变正常地图的手感。

`test/tutorial.test.ts` —— 教学脚本可完成性：

- 一个只走公开操作（不直接改状态）的 driver 必须把 27 步全部走完并抵达完成界面
- 两层关卡都要走到
- 走完后法术套装、已购升级、锻造出的白霜戒都必须在位
- 巫师全程不得死亡
- 当前步骤没要求的操作必须被拒绝，而 `play`/`menu`/`help` 三个逃生口必须始终可用

这个 driver 抓到了两个真实的卡死：`cast` 步禁止移动会让射程外的固定靶变成死局（现在
移动无条件放行）；`move` 步缺少完成条件时"走一步就算过"（现在按是否站上目标格判定）。
driver 自己也踩过一次坑——手写切比雪夫距离判断射程，而游戏用的是欧氏距离，于是改成直接
问 `validTarget`，不复制公式。
